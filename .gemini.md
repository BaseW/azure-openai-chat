# Gemini Project Directives

This document provides guidance for Gemini on how to interact with the `azure-openai-chat` project. It is a summary of the project's goals, structure, and technical stack, derived from the `.kiro/steering/` directory.

---

## Product Overview (from .kiro/steering/product.md)

This is a CLI chat application that integrates with Azure OpenAI API. The application allows users to:

- Chat with Azure OpenAI models through a terminal interface
- Save and load conversation history
- Create named sessions for different conversation contexts
- Stream responses from the AI in real-time

The application is built with Ink and React to provide a rich terminal UI experience. It uses TypeScript for type safety and follows a modular architecture with clear separation of concerns.

### Key Features

- Real-time streaming of AI responses
- Persistent storage of conversations
- Session management
- Error handling and recovery
- Secure file storage with proper permissions

## Project Structure (from .kiro/steering/structure.md)

### Directory Organization

```
azure-openai-chat/
├── dist/               # Compiled JavaScript output
├── docs/               # Documentation files
│   ├── feature-requests.md
│   └── todos.md
├── src/                # Source code
│   ├── components/     # React/Ink UI components
│   │   ├── App.tsx     # Main application component
│   │   └── MessageList.tsx # Message display component
│   ├── types/          # TypeScript type definitions
│   │   └── index.ts    # Shared type interfaces
│   ├── utils/          # Utility functions and services
│   │   ├── azure.ts    # Azure OpenAI API integration
│   │   └── storage/    # Storage implementation
│   │       ├── __tests__/           # Test files for storage
│   │       │   └── fileStorage.test.js  # Tests for file storage
│   │       ├── fileStorage.ts       # File-based storage service
│   │       ├── index.ts             # Storage exports
│   │       ├── interfaces.ts        # Storage interfaces
│   │       ├── paths.ts             # File path utilities
│   │       └── permissions.ts       # File permission utilities
│   └── index.tsx       # Application entry point
```

### Key Architectural Components

- **Components**: `App` (main container), `MessageList` (message rendering).
- **Types**: `Message`, `ChatState`, `Config`.
- **Storage**: `StorageService` interface, `FileStorageService` implementation.
- **Testing**: Co-located in `__tests__` directories, using Jest.

### Architectural Patterns

1.  **Service-based architecture**: Clear interfaces, swappable implementations.
2.  **Component composition**: React component hierarchy.
3.  **Consistent Error handling**: Custom error hierarchy.
4.  **Feature-based file organization**.

## Technical Stack & Guidelines (from .kiro/steering/tech.md)

### Core Technologies
- **Language**: TypeScript
- **Runtime**: Node.js
- **UI Framework**: Ink (React for CLI)
- **Module System**: ES Modules (ESM)

### Key Libraries
- `@azure/openai`
- `ink`
- `ink-text-input`

### Development Tools & Build System
- **Package Manager**: pnpm
- **Build Tool**: TypeScript compiler (`tsc`)
- **Testing**: Jest
- **Linting/Formatting**: ESLint, Prettier

### Project Commands
- `pnpm install`: Install dependencies
- `pnpm build`: Build the project
- `pnpm start`: Run the application
- `pnpm test`: Run tests
- `pnpm lint`: Lint code
- `pnpm format`: Format code

### Environment Configuration
- `AZURE_OPENAI_ENDPOINT`
- `AZURE_OPENAI_API_KEY`
- `AZURE_OPENAI_DEPLOYMENT_NAME`

### Code Style & Testing Guidelines
- Use ES Modules with explicit `.js` extensions in imports.
- Follow TypeScript strict mode.
- Use interfaces for type definitions.
- Implement proper error handling with custom error classes.
- Use async/await.
- Mock external dependencies in tests (e.g., `fs`, `path`).
- Follow conventional commit message format.
- Use feature branches and rebase before merging.
